# Banana Pi BPI-R3 OpenWrt ImageBuilder Pipeline

Современный и быстрый репозиторий для автоматической сборки кастомной прошивки под **Banana Pi BPI-R3** на базе официального **OpenWrt ImageBuilder**.

## Что делает репозиторий

Вместо компиляции исходного кода OpenWrt с нуля (что занимает часы и часто приводит к ошибкам зависимостей ядра), этот пайплайн использует официальный **OpenWrt ImageBuilder**. 

- Архив ImageBuilder кэшируется GitHub Actions по версии и SHA-256: первый запуск каждой версии скачивает архив, повторные используют кэш.
- Дополнительные пакеты можно передать прямо при ручном запуске workflow, не меняя конфигурацию репозитория.
- 🚀 Публикация готовых `.img.gz` образов и списка пакетов (`.manifest`) в GitHub Releases.

## Структура

- `.github/workflows/reusable-openwrt-build.yml` — ядро сборки на базе ImageBuilder.
- `.github/workflows/build.yml` — сборка артефактов без публикации (для тестов).
- `.github/workflows/release.yml` — сборка и автоматическое создание GitHub Release.
- `.config/config` — список кастомных пакетов, которые вы хотите добавить в прошивку.

## Как работает CI/CD

### Ручной запуск (Workflow Dispatch)
При запуске экшена можно указать:
1. **OpenWrt version to use**: Версия OpenWrt (по умолчанию `24.10.5`). Можно указать, например, `25.12.0`.
2. **Additional package names for this build**: Дополнительные пакеты через пробел, например `curl nano`. Они действуют только для текущей сборки и добавляются к пакетам из `.config/config`.
3. **Custom build number override (optional)**: Только для Release workflow; переопределяет номер билда в названии релиза.

### Результат сборки
В разделе Artifacts (или в Releases) появятся:
- `*bananapi_bpi-r3-sdcard.img.gz` — образ для записи на SD-карту.
- `*bananapi_bpi-r3.manifest` — текстовый файл с полным списком всех установленных в прошивку пакетов.
- `sha256sums` — контрольные суммы.

## Как менять состав пакетов

Базовый список хранится в `.config/config`:

1. Добавьте пакет в формате `CONFIG_PACKAGE_<name>=y` или `=m`.
2. Сделайте commit/push.

Для разового запуска без изменения репозитория укажите пакеты в поле **Additional package names for this build**, например:

```text
curl nano
```

Workflow объединит этот список с `.config/config`, проверит доступность пакетов через `make manifest`, а затем соберёт образ. Если пакет недоступен в выбранной версии OpenWrt или имя указано с ошибкой, сборка завершится до создания образа.

Пакеты AmneziaWG временно отключены до появления совместимого upstream-релиза для выбранной версии OpenWrt.

## AmneziaWG

AWG-пакеты и feed временно отключены. Причина — внешний проект пока не публикует совместимые пакеты для OpenWrt `25.12.6`.

## Быстрый старт

1. Залейте этот код в свой репозиторий на GitHub.
2. В настройках репозитория откройте `Settings -> Actions -> General` и включите GitHub Actions.
3. Перейдите во вкладку **Actions** и выберите workflow:
   - **Build OpenWrt Firmware (Build-Only)** — тестовая сборка, результат будет в Artifacts.
   - **Build OpenWrt Firmware (Release)** — сборка с публикацией GitHub Release.
4. Нажмите **Run workflow** и заполните поля:
   - `OpenWrt version to use`: например `25.12.6`.
   - `Additional package names for this build`: например `curl nano` или оставьте пустым.
   - `Custom build number override`: только для Release workflow, необязательно.
5. Для первой проверки используйте **Build-Only**. После завершения откройте job и проверьте `bananapi_bpi-r3.manifest`.

## Время сборки и кэш

Старый Release run `#17` от 9 марта 2026 года занял 2 минуты 56 секунд целиком (job сборки — 2 минуты 41 секунду) на OpenWrt `24.10.5` и использовал короткий статический список пакетов. Run `#36` на `25.12.6` занял 5 минут 59 секунд; из них 5 минут 14 секунд ушло на скачивание ImageBuilder размером 577,457,793 байта, после чего сборка упала из-за недоступных FTP-пакетов.

После исправления пакетов и добавления кэша Build-only run `#37` собрал `25.12.6` с `curl nano` за 3 минуты 21 секунду и сохранил архив. Повторный run `#38` также собрал образ с `curl nano` за 1 минуту 38 секунд: restore, проверка и распаковка ImageBuilder заняли 3 секунды вместо 1 минуты 42 секунд на первом заполнении.

Кэш ImageBuilder привязан к версии и SHA-256 архива. При изменении upstream checksum создаётся новая запись. Package feeds и результаты `make image` не кэшируются.

## Установка и прошивка (Banana Pi BPI-R3)

Плата BPI-R3 имеет переключатели (джамперы) для выбора устройства загрузки. 
- **1** = On/Вверх
- **0** = Off/Вниз
- **X** = Не имеет значения (вторичный селектор)

| Режим загрузки | A | B | C (NAND/NOR) | D (SD/eMMC) |
| :--- | :--- | :--- | :--- | :--- |
| **SD Карта** | 1 | 1 | X | 1 |
| **eMMC** | 0 | 1 | X | 0 |
| **NAND** | 1 | 0 | 1 | X |
| **NOR** | 0 | 0 | 0 | X |

### 1. Загрузка с SD-карты
1. Скачайте файл `*bananapi_bpi-r3-sdcard.img.gz` из релизов.
2. Запишите его на SD-карту с помощью **BalenaEtcher**, **Rufus** или через терминал (`dd`).
3. Установите переключатели в режим **SD Карта** (A=1, B=1, C=1, D=1).
4. Вставьте карту и включите роутер.

### 2. Установка во внутреннюю память (eMMC / NAND / NOR)
Загрузившись с SD-карты, вы можете перенести систему во внутреннюю память прямо из терминала OpenWrt (через SSH):

**Перенос в NAND:**
```bash
fw_setenv bootcmd "env default bootcmd ; saveenv ; run ubi_init ; bootmenu 0"
reboot
```
*(После перезагрузки установите джамперы в режим NAND: A=1, B=0, C=1, D=0)*

**Перенос в NOR:**
```bash
fw_setenv bootcmd "env default bootcmd ; saveenv ; run nor_init ; bootmenu 0"
reboot
```
*(Джамперы в режим NOR: A=0, B=0, C=0, D=0)*

**Перенос в eMMC (с NAND):**
```bash
fw_setenv bootcmd "env default bootcmd ; saveenv ; run emmc_init ; bootmenu 0"
reboot
```
*(Джамперы в режим eMMC: A=0, B=1, C=1, D=0)*
